## 2026-11-20 — 문서 구조와 개발 기록 페이지 준비

### 오늘 한 일

- README의 목차에서 연결하는 개발 기록 페이지가 존재하지 않아 `docs/development-log/README.md`를 추가했습니다.
- 개발 기록을 날짜별로 정리하고, 해결한 문제와 후속 개선을 함께 남길 수 있도록 기본 형식을 마련했습니다.

### 해결한 문제

- **문제:** README의 “개발 기록 모아보기” 링크를 열면 대상 파일이 없어 404가 발생했습니다.
- **해결:** 링크가 가리키는 경로에 이 README를 생성했습니다. 이후 개별 개발 항목을 추가할 때도 날짜와 제목을 기준으로 이 페이지에서 찾아갈 수 있습니다.

### 배운 점

- README에 링크를 추가할 때는 실제 파일이 저장소에 존재하는지와 경로의 대소문자가 일치하는지 함께 확인해야 합니다.
- 개발 기록은 결과만 나열하기보다 문제, 원인, 선택한 해결책, 확인 방법을 남겨야 나중에 같은 상황을 빠르게 이해할 수 있습니다.

### 다음에 개선할 점

- 기능 작업이나 버그 수정이 진행될 때마다 아래 형식으로 별도 항목을 추가합니다.
- 기록이 많아지면 월별 페이지로 나누고, 이 목록에서 각 기록으로 연결합니다.
- 실제 구현 사항과 확인 결과를 근거로 작성하고, 추측을 사실처럼 기록하지 않습니다.

## 기록 작성 템플릿

새 작업을 기록할 때 아래 템플릿을 복사해 사용하세요.

```markdown
## YYYY-MM-DD — 작업 제목

### 오늘 한 일
- 무엇을 변경하거나 구현했는지

### 해결한 문제
- 문제와 재현 상황:
- 원인:
- 해결 방법:
- 확인 방법과 결과:

### 배운 점
- 새로 알게 된 점이나 다음에 활용할 원칙

### 다음에 개선할 점
- 남은 작업이나 후속 검토 항목
```

## 기록 원칙

- **구체적으로 쓰기:** “버그 수정” 대신 어떤 상황에서 문제가 생겼고 어떻게 고쳤는지 적습니다.
- **검증 결과 남기기:** 테스트, 빌드, 수동 확인 중 실제로 실행한 방법만 기록합니다.
- **결정 이유 기록하기:** 선택한 방법뿐 아니라 고려한 대안과 선택 이유도 적습니다.
- **개인정보·비밀 값 제외하기:** 토큰, 비밀번호, 실제 사용자 정보, 비밀 환경 변수는 기록하지 않습니다.
- **후속 작업 분리하기:** 완료한 일과 아직 하지 않은 개선점을 구분합니다.
